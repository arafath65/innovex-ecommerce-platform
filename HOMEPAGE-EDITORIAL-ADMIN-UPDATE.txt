INNOVEX ECOMMERCE - HOMEPAGE EDITORIAL ADMIN UPDATE

WHAT THIS ADDS
- Store Admin > Homepage editor at /admin/homepage.
- Per-store editable eyebrow, heading, description, button label and button path.
- Four individually managed images with preview, replace and remove actions.
- Optional alt text and optional internal store link for each image.
- Uploads are validated and optimized to WebP, then stored outside the Next.js app using the existing MEDIA_STORAGE_ROOT storage service.
- Images are isolated by store ID and slot under:
  stores/{storeId}/homepage-editorial/slot-{1..4}/
- The homepage editorial banner is loaded from the logged-in storefront's database relation.
- The banner appears only when the store enabled it and all four images have been uploaded.
- Store Admin authorization is restricted to active OWNER/ADMIN users belonging to the current store.
- The existing New Arrivals and Flash Sale sections are retained; the removed Kitchen Companion component stays removed from HomeClient.

INSTALLATION (LOCAL DEVELOPMENT)
1. Stop Next.js with Ctrl+C.
2. Back up your project folder.
3. Extract this ZIP into the root of:
   C:\Users\Pradeep\Downloads\innovex-ecommerce-platform
   Allow the included files to overwrite the matching source files.
4. Run:
   npx prisma generate
   npx prisma migrate dev
   npm run lint
5. Start the app:
   npm run dev
6. Open the appropriate store admin domain:
   http://oscar-trading.test:3000/admin/homepage
   http://second-store.test:3000/admin/homepage

ADMIN USE
- Enter the small heading, main heading, description, button label and button link.
- Upload images 1, 2, 3 and 4. JPG, PNG and WebP are accepted; maximum original size is 10 MB each.
- Add accessible image descriptions and optional internal paths if desired.
- Save the content, then enable the section and save again if needed.
- All four images are required before enabling the section.
- Each store has a separate record and separate upload folder.

DATABASE / DEPLOYMENT
- The Prisma migration only creates the new store_homepage_editorial table and its foreign key/indexes. It does not alter product, category, order, customer or existing store data.
- For a later production deployment, apply the migration with `npx prisma migrate deploy` after the updated source and Prisma Client are deployed.
- Keep MEDIA_STORAGE_ROOT pointed to a persistent directory outside the Next.js app directory. Back up that directory together with MySQL.
- No R2 configuration is required for this update.

VALIDATION
- TypeScript/TSX source syntax parsing and structural checks passed in the packaging environment.
- A full application ESLint run, Prisma validation/generation and Next.js build must be run in the user's project after extraction, where the project's dependencies and database are available.
